# 历史开发集评估规则（合成句，非正式测试）

本文件记录此前原版开发集的评估规则与实际流程，不是现行正式评分口径。正式候选已选择 `compact-dev-v2`；未来正式评估按 [`FORMAL_SCORING_V3.md`](FORMAL_SCORING_V3.md) 逐字段、子集与有效响应分别评分。历史开发报告保持原貌。

## 结构与意图校验分开

一次调用先看 API 是否返回可解析的完整 JSON，再看正式 Schema 的必填键与类型是否齐全，最后运行本地取值、逐字证据和约束校验。结构完整不等于意图判断正确。前一次单句正式预检返回了完整九字段，但在 `missing_evidence:trajectory` 处被拒绝；它不是成功预检，不能事后创建成功标记。

## `trajectory` 证据统一口径

- `from_to` 是明确指定歌曲编排顺序，必须有原句中逐字连续的证据。
- `none` 表示没有可编码的歌曲顺序或情绪／活跃度目标，`evidence.trajectory` 必须为 `null`。
- `single_target` 是由已明确的音乐情绪或活跃度目标推得的“有目标、无歌曲顺序”分类。“没有指定顺序”本身往往没有可引用的独立短语，因此 `evidence.trajectory` 可以是 `null`。若模型提供了非空证据，它仍须逐字连续出现在原句中。
- 其他非空意图字段与每项不支持条件的原句证据要求保持不变。不会自动补造证据，也不会改变作者已批准的 V2 答案。

## 开发集预先固定的评分与停止规则

只使用现有 12 条 `dev_*` 合成句和作者已批准的答案；开发集不依赖正式测试集冻结记录。每句最多调用一次；连续三次 API 或结构／格式失败时停止。证据失败、合法结构中的越界数值，以及通过本地校验但与标准答案不符的字段判断，分别记录，不混成格式失败。

六个核心字段分别报告正确数／全部 12 条、正确数／已调用条数、正确数／本地有效条数；未调用的句子在 12 条覆盖列中是“未完成”，不是模型判断错误。另列整卡、`requires_melody_present`、不支持条件原词集合、`cannot_guarantee_constraint` 返回状态及关键词基线。失败调用计入已调用端到端分母，但不当作模型对不支持条件原词的误报或漏报；仅有效输出才计算原词命中、误报、漏报。费用按可取得的 token 和模型标价估算。

评估请求只发送开发句原话、固定运行时 system 提示词与完整正式 Schema；不会发送标准答案。报告与逐句轨迹只保留案例 ID、固定错误类别和字段名、数量及 token，不保存完整模型回复或模型生成的未知字段和值。结果文件位于 `reports/dev_evaluation.*`；它们不是正式测试成绩，也不会创建 `data/connection_preflight.json`。
